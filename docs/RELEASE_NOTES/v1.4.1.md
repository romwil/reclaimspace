## Reclaimspace v1.4.1

Saving the Unraid API URL and key on Configuration now sticks, and the next Appdata scan uses them.

### Highlights

- **Save keeps the Unraid connection** — the URL you entered stays on Configuration after you leave and come back. The key stays saved; the field stays blank and shows that a key is already there, so you do not retype it
- **Appdata can see that connection** — Scan uses the URL and key from Configuration. A blank API key on the container no longer erases the one you saved, and the template's default URL no longer replaces a URL you changed
- **Still fails closed** — if neither a saved Unraid API connection nor a Docker socket is available, Scan stops and does not list folders as unused

### Fixed

- `load_merged_settings` ignores an environment variable that is unset, and a blank value no longer replaces a non-empty value in `settings.json`
- A non-empty `unraid_api_url` or `unraid_api_key` stored in `settings.json` is what Configuration and Appdata read, even when the container exports the template default URL or a blank key
- A later save with a blank key keeps the stored key. A non-empty key in the save body is written
- After Save, Configuration fills the URL from the saved settings and marks the key as set

### Upgrade from v1.4.0

```bash
docker pull romwil/reclaimspace:1.4.1
```

Keep the existing config directory, reports, media mounts, appdata mount, and code mount. Recreate the container with the new image. Do not replace `settings.json`, and do not delete reports or the appdata share.

Open `http://your-server:8777/config`. The Unraid API URL you saved should be filled in, and the key field should show that a key is saved. `/api/health` should report `1.4.1`. Then run an Appdata scan when you are ready. This release does not change quarantine or delete behavior.
