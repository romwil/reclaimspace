## Reclaimspace v1.4.3

Appdata Migrate no longer holds the page on “Moved…” while a folder copies onto the code share. The page shows which folder is moving, and the buttons come back when that folder finishes or cannot be moved.

### Highlights

- **The page comes back** — Migrate runs in the background. You see the current folder, and a failure is written out instead of an endless spinner
- **One folder at a time** — each folder is checked again, just before it moves, for a container mount, a code marker, and a destination that is already there
- **No merge** — if the code folder already exists, or the appdata folder is already gone, that folder stops and the two trees are left as they are
- **Same quarantine and delete** — archive, restore, delete, and purge behave as they did in v1.4.2

### Fixed

- `POST /api/appdata/migrate` returns a job id immediately. `GET /api/appdata/migrate/{job_id}` reports queued, running, completed, or failed, plus the current folder
- A second migrate of a name that is already moving is refused
- A cross-device move copies file bytes and recreates symlinks. It does not `chmod` or restamp the destination, which could block forever on the Unraid user share
- FIFOs, sockets, and other special files are refused without being opened
- A failure on one folder is stored on the job and is not reported as a full success

### Upgrade from v1.4.2

```bash
docker pull romwil/reclaimspace:1.4.3
```

Keep the existing config directory, reports, media mounts, appdata mount, and code mount. Recreate the container with the new image. Do not replace `settings.json`, and do not delete reports or the appdata share.

Open `http://your-server:8777/appdata`. `/api/health` should report `1.4.3`. This release does not migrate, quarantine, delete, or purge anything by itself. Run Migrate only when you mean to move a code folder.
