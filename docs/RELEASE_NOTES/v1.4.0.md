## Reclaimspace v1.4.0

Leftover appdata folders can be reviewed in the browser. Media duplicates still go to quarantine and are never deleted.

### Highlights

- **Appdata** — a new page lists top-level folders on the appdata share that no container is using
- **In use stays put** — a folder mounted by any container, running or stopped, cannot be quarantined, migrated, or deleted. A mount of the whole share protects every folder
- **Migrate** — a folder that looks like a project can move from appdata to your code directory after you confirm the source, destination, and size
- **Quarantine, then decide** — unused folders move into `appdata/_archive` with a manifest. Restore puts them back. Delete and Purge are permanent and name each folder before they run
- **Read-only Docker check** — point Configuration at an Unraid API key that has only `DOCKER:READ_ANY`. The scan fails closed when that source is missing

### Added

- `/appdata` for unused folders, one-level explore, migrate, quarantine, delete, empty-folder sweep, and archive restore or purge
- Host paths `/mnt/user/appdata/<name>` and `/mnt/cache/appdata/<name>` match the same folder inside `/appdata`
- Code detection: a `.git` directory, or at least two of `package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`, `pom.xml`, `build.gradle`, a `*.sln` file, or `.code-workspace`
- Configuration fields for appdata root, code root, host prefixes, Unraid API URL, and a masked API key. **Test** checks that Docker can be read and does not list mounts
- Compose, `docker-run.sh`, and the Unraid template mount `/mnt/cache/appdata` at `/appdata` and `/mnt/user/data/code` at `/code`. They do not mount the Docker socket

### Changed

- The header links Media, Appdata, and Configuration. Media quarantine behavior is unchanged

### Upgrade from v1.3.0

```bash
docker pull romwil/reclaimspace:1.4.0
```

Keep the existing config directory, reports, media mounts, and quarantine folder. Recreate the container with the new image and add:

- `/mnt/cache/appdata` → `/appdata`
- `/mnt/user/data/code` → `/code`

Do not mount `docker.sock`. Do not replace `settings.json`, and do not delete the quarantine folder or the appdata share.

Open `http://your-server:8777/` and `http://your-server:8777/appdata`. `/api/health` should report `1.4.0`. Before the first Appdata scan, create an Unraid API key with only `DOCKER:READ_ANY` and save it under **Configuration → Appdata**.
