## Reclaimspace v1.4.2

Appdata Scan now treats a folder as in use only when a container mounts that folder. Mounting the appdata share so Reclaimspace can read it no longer marks every leftover folder as in use.

### Highlights

- **Unused means unmounted** — a top-level folder is in use only when a container, running or stopped, bind-mounts that folder or a path inside it
- **The scan mount is ignored** — Reclaimspace mounts `/mnt/cache/appdata` so it can read the share. A mount of that share root, with no folder after it, no longer protects every directory
- **Still fails closed** — if the Unraid API and the Docker socket cannot be read, Scan stops and does not list folders as unused. `_archive` stays out of the unused list

### Fixed

- Classification ignores container mounts whose source is exactly `/mnt/user/appdata` or `/mnt/cache/appdata`
- A mount of `/mnt/cache/appdata/<name>` or `/mnt/user/appdata/<name>/...` still marks only that folder in use, including when the container is stopped
- Quarantine, delete, migrate, and empty-folder removal use the same rule

### Upgrade from v1.4.1

```bash
docker pull romwil/reclaimspace:1.4.2
```

Keep the existing config directory, reports, media mounts, appdata mount, and code mount. Recreate the container with the new image. Do not replace `settings.json`, and do not delete reports or the appdata share.

Open `http://your-server:8777/appdata` and run Scan. `/api/health` should report `1.4.2`. Folders that no container mounts appear under unused. Folders a container still mounts stay in use. This release does not quarantine, delete, or migrate anything by itself.
